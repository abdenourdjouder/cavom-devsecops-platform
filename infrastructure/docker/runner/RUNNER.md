# GitLab Runner

The default runner has no Docker socket, host mounts, added capabilities, or privileged mode. It runs as numeric UID/GID 1000, has a read-only root filesystem, and uses the shell executor with an ephemeral workspace. Registration and repository state are not placed in source control.

Copy `config.toml.example` to the ignored `config.toml`, replace its token with an instance, group, or project runner authentication token generated by GitLab, and set `GITLAB_RUNNER_CONFIG=./runner/config.toml`. Keep that file owner-readable and preserve it securely across host replacement. Registration tokens must not be reused as authentication tokens.

The optional `buildkit` profile is the alternative to privileged Docker-in-Docker. It starts `moby/buildkit` in rootless mode with its unprivileged daemon state and Unix socket in named volumes. It deliberately retains `seccomp=unconfined` and `apparmor=unconfined`, which are required by rootless BuildKit's current namespace operation; the runner itself does not receive that relaxation. Jobs can use a pinned image containing `buildctl` and `BUILDKIT_HOST=unix:///run/buildkit/buildkitd.sock`. Do not enable a Docker socket or `privileged = true` as a convenience.

To use the optional service, include the `buildkit` profile when selecting the Compose configuration; no service is started during setup of this repository. Images intended for CI should be version-pinned, approved, and optionally allowlisted in a protected runner policy.
